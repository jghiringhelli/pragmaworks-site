The Seven GS Properties Las Siete Propiedades GS

A Generative Specification scores 0–2 on each property. 14 = fully healthy. Each property addresses a specific way an AI-assisted codebase degrades without it. Score 0 has a name — find it at /diseases. Una Especificación Generativa puntúa 0–2 en cada propiedad. 14 = completamente saludable. Cada propiedad aborda una forma específica en que una base de código asistida por IA se degrada sin ella. El puntaje 0 tiene un nombre — encuéntralo en /diseases.

Property 1 of 7 Propiedad 1 de 7

Self-describing Auto-descriptiva

Any session can read the codebase and derive full context without external explanation. Cualquier sesión puede leer la base de código y derivar contexto completo sin explicación externa.

2
SPEC.md, CLAUDE.md (or AGENTS.md), and STATUS.md exist and are current. The AI reads them at session start and derives intent, constraints, and architecture without any additional prompting.SPEC.md, CLAUDE.md (o AGENTS.md) y STATUS.md existen y están actualizados. La IA los lee al inicio de la sesión y deriva intención, restricciones y arquitectura sin prompting adicional.
1
A README exists with purpose but key architectural decisions, constraints, or non-goals are not written down. The AI can read what the system does but not why it is structured as it is.Existe un README con propósito, pero las decisiones arquitectónicas clave, restricciones o no-objetivos no están escritos. La IA puede leer qué hace el sistema pero no por qué está estructurado así.
0
Empty Map. Intent lives in the original author's head. A new AI session cannot determine what the system is supposed to do or why constraints exist — so it fills in the blanks from training data.Mapa Vacío. La intención vive en la cabeza del autor original. Una nueva sesión de IA no puede determinar qué se supone que hace el sistema ni por qué existen las restricciones — así que llena los blancos desde el training data.
→ Empty Map — full disease card → Mapa Vacío — tarjeta de enfermedad completa
Property 2 of 7 Propiedad 2 de 7

Bounded Acotada

Every module and function has a single declared responsibility. Explicit size limits enforced. Cada módulo y función tiene una responsabilidad única declarada. Límites de tamaño explícitos aplicados.

2
Explicit size limits declared in the spec (max file length, max function length) and enforced in CI. Every module has a single declared responsibility. Files fit within any AI's read window — no silent truncation.Límites de tamaño explícitos declarados en la spec (longitud máxima de archivo, longitud máxima de función) y aplicados en CI. Cada módulo tiene una responsabilidad única declarada. Los archivos caben dentro de la ventana de lectura de cualquier IA — sin truncación silenciosa.
1
Most modules are well-scoped. Some files have grown over time. No enforced size limits — the AI may be silently reading truncated files in some sessions.La mayoría de los módulos están bien delimitados. Algunos archivos han crecido con el tiempo. Sin límites de tamaño aplicados — la IA puede estar leyendo silenciosamente archivos truncados en algunas sesiones.
0
Spreading Boundary. Responsibilities have crept outward. Files exceed the AI's read budget and are silently truncated. The AI edits against an incomplete view and adds code that contradicts what it couldn't see.Frontera Expansiva. Las responsabilidades se han expandido. Los archivos superan el presupuesto de lectura de la IA y se truncan silenciosamente. La IA edita contra una vista incompleta y agrega código que contradice lo que no pudo ver.
→ Spreading Boundary — full disease card → Frontera Expansiva — tarjeta de enfermedad completa
Property 3 of 7 Propiedad 3 de 7

Composable Componible

Clean module interfaces. Declared dependency direction. Changes are local, not cascading. Interfaces de módulo limpias. Dirección de dependencias declarada. Los cambios son locales, no en cascada.

2
Dependency direction declared in the spec (e.g., domain → application → infrastructure, never reversed). No circular imports. A change in one module does not require changes in others unless the interface changes.Dirección de dependencias declarada en la spec (p.ej., dominio → aplicación → infraestructura, nunca invertido). Sin importaciones circulares. Un cambio en un módulo no requiere cambios en otros a menos que cambie la interfaz.
1
Most modules are reasonably independent. Some circular dependencies or undeclared coupling exist. The AI can usually work within a module but occasionally needs to read widely to understand blast radius.La mayoría de los módulos son razonablemente independientes. Existen algunas dependencias circulares o acoplamiento no declarado. La IA generalmente puede trabajar dentro de un módulo pero ocasionalmente necesita leer ampliamente para entender el radio de impacto.
0
Tangled Web. Circular imports. A single change cascades to five other modules. The AI cannot model the blast radius of any change without reading the entire codebase — and hallucinated side effects proliferate.Red Enmarañada. Importaciones circulares. Un solo cambio se propaga en cascada a otros cinco módulos. La IA no puede modelar el radio de impacto de ningún cambio sin leer toda la base de código — y los efectos secundarios alucinados proliferan.
→ Tangled Web — full disease card → Red Enmarañada — tarjeta de enfermedad completa
Property 4 of 7 Propiedad 4 de 7

Verifiable Verificable

Every spec claim is backed by a running test. The AI can verify its own output against declared intent. Cada afirmación de la spec está respaldada por una prueba en ejecución. La IA puede verificar su propio output contra la intención declarada.

2
Test pyramid complete: unit at function boundaries, integration at module boundaries, end-to-end at use case boundaries. Every F-NNN feature in SPEC.md has at least one passing acceptance test. The AI runs tests and verifies output before closing any session.Pirámide de pruebas completa: unitarias en fronteras de función, integración en fronteras de módulo, end-to-end en fronteras de caso de uso. Cada funcionalidad F-NNN en SPEC.md tiene al menos una prueba de aceptación pasando. La IA corre pruebas y verifica el output antes de cerrar cualquier sesión.
1
Unit tests exist and pass. Integration or behavioral coverage is sparse. Some spec claims are not backed by tests — the AI generates code that looks correct but cannot be verified against declared intent.Las pruebas unitarias existen y pasan. La cobertura de integración o conductual es escasa. Algunas afirmaciones de la spec no están respaldadas por pruebas — la IA genera código que parece correcto pero no puede verificarse contra la intención declarada.
0
Unbound Spec. No executable tests, or tests cover implementation details rather than behavior. The AI generates, the output looks plausible, and the session closes. Defects surface in production — or not at all.Spec Sin Límites. Sin pruebas ejecutables, o las pruebas cubren detalles de implementación en lugar de comportamiento. La IA genera, el output parece plausible, y la sesión cierra. Los defectos aparecen en producción — o no aparecen.
→ Unbound Spec — full disease card → Spec Sin Límites — tarjeta de enfermedad completa
Property 5 of 7 Propiedad 5 de 7

Auditable Auditable

Every architectural decision is traceable. The AI reads the why before modifying any constraint. Cada decisión arquitectónica es trazable. La IA lee el por qué antes de modificar cualquier restricción.

2
Conventional Commits enforced on every commit. ADR directory with decision records for all architectural choices. The AI can always answer: why is this constraint here, who decided, and when. Intentional tradeoffs cannot be mistaken for bugs.Conventional Commits aplicados en cada commit. Directorio de ADRs con registros de decisión para todas las elecciones arquitectónicas. La IA siempre puede responder: por qué está aquí esta restricción, quién decidió y cuándo. Los tradeoffs intencionales no pueden confundirse con bugs.
1
Commit messages are inconsistent — some are descriptive, most are not. Some ADRs exist for major decisions but not systematically maintained. The AI can identify some constraints but not all.Los mensajes de commit son inconsistentes — algunos son descriptivos, la mayoría no. Algunos ADRs existen para decisiones mayores pero no se mantienen sistemáticamente. La IA puede identificar algunas restricciones pero no todas.
0
Amnesia Stack. No commit discipline. No ADRs. The AI encounters a constraint that looks suboptimal and "corrects" it — because the rationale for that constraint does not exist anywhere the AI can read. Over many sessions, every intentional tradeoff gets normalized away.Pila Amnésica. Sin disciplina de commits. Sin ADRs. La IA encuentra una restricción que parece subóptima y la "corrige" — porque la justificación de esa restricción no existe en ningún lugar que la IA pueda leer. A lo largo de muchas sesiones, cada tradeoff intencional se va normalizando.
→ Amnesia Stack — full disease card → Pila Amnésica — tarjeta de enfermedad completa
Property 6 of 7 Propiedad 6 de 7

Defended Defendida

Trust boundary declared. Irreversible operations classified. The AI generates defensive code by default. Trust boundary declarado. Operaciones irreversibles clasificadas. La IA genera código defensivo por defecto.

2
Trust boundary explicitly declared in SPEC.md. Input validation required at every API boundary. Irreversible operations classified and gated. Secrets in environment only — enforced in the architectural constitution. The AI observes these patterns and replicates them in all new code.Trust boundary declarado explícitamente en SPEC.md. Validación de input requerida en cada boundary de API. Operaciones irreversibles clasificadas y protegidas. Secretos solo en entorno — aplicado en la constitución arquitectónica. La IA observa estos patrones y los replica en todo el código nuevo.
1
Some validation in place at key endpoints. Secrets management inconsistent. Not all trust boundaries explicitly declared. The AI applies defensive patterns to familiar code but adds new attack surface on unfamiliar paths.Algo de validación en endpoints clave. Gestión de secretos inconsistente. No todos los trust boundaries declarados explícitamente. La IA aplica patrones defensivos en código familiar pero agrega nueva superficie de ataque en rutas no familiares.
0
Open Gates. No declared trust boundary. Secrets in source. Error responses leak internals. The AI replicates the undefended patterns it observes — every new endpoint is generated in the style of the existing unprotected codebase.Puertas Abiertas. Sin trust boundary declarado. Secretos en código fuente. Las respuestas de error filtran internos. La IA replica los patrones no defendidos que observa — cada nuevo endpoint se genera en el estilo de la base de código existente sin protección.
→ Open Gates — full disease card → Puertas Abiertas — tarjeta de enfermedad completa
Property 7 of 7 Propiedad 7 de 7

Executable Ejecutable

Every spec claim is backed by a passing test. CI enforced. Runnable from a clean clone. Cada afirmación de la spec está respaldada por una prueba pasando. CI aplicado. Ejecutable desde un clone limpio.

2
The spec is live: every claim maps to a passing test. CI runs on every commit to the main branch. The project runs from a clean clone with only the manifest as setup guide — no tribal knowledge required. Spec and implementation are in sync.La spec está viva: cada afirmación mapea a una prueba pasando. CI corre en cada commit a la rama main. El proyecto se ejecuta desde un clone limpio con solo el manifiesto como guía de setup — sin conocimiento tribal requerido. Spec e implementación están en sincronía.
1
CI exists but not fully enforced on all branches. Some spec sections are not backed by executable tests. The project mostly runs from clone but requires some undocumented steps. Spec and implementation occasionally drift.CI existe pero no completamente aplicado en todas las ramas. Algunas secciones de la spec no están respaldadas por pruebas ejecutables. El proyecto mayormente se ejecuta desde clone pero requiere algunos pasos no documentados. La spec y la implementación ocasionalmente divergen.
0
Frozen Spec. The spec describes behavior the system does not exhibit. The AI reads the spec and believes it — generating correct code for a fiction. Spec and implementation diverge further with every session.Spec Congelada. La spec describe comportamiento que el sistema no exhibe. La IA lee la spec y la cree — generando código correcto para una ficción. La spec y la implementación divergen más con cada sesión.
→ Frozen Spec — full disease card → Spec Congelada — tarjeta de enfermedad completa
