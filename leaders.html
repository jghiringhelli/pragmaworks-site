Get a real audit of one of your team's repos. By dinner.

If you're a tech lead, engineering manager, VP, or CTO and your team has been using AI assistance for code generation, your codebase is changing in ways your usual review cadence can't catch. This guide gets you a manager-grade report on one of your repos in an afternoon — including the team-habit and AI-bug analysis no static analyzer surfaces.

Who this is for. This page is for leaders running existing engineering teams. If you're starting a brand-new project, the developer cookbook covers that path. If you're not technical enough to run an AI assistant yourself, hand this page to your tech lead — the conversation works the same way and they bring you the result.

What you'll get

at the end of the afternoon
  • An initial audit PDF. Eight sections including the seven GS properties scored 0-2 with evidence, structural-discipline assessment, test pyramid coverage, documentation health, security/logging baseline, and a prioritized remediation plan.
  • A team-habit report (separate PDF). Last 90 days of commit history analyzed: PR review density, regression coverage of past bugs, AI-introduced bug rate, commit-size distribution, collaboration graph across team members. Charts. The organizational metrics no other tool surfaces.
  • An after-report PDF. If you choose to apply remediations, a side-by-side comparison of initial vs. final state with deltas you can show your CEO or board.
  • A working test harness. Spec-derived behavioral verification running against your application — the foundation that lets your team use AI assistance safely going forward.
  • An optional Chronicle install. Persistent organizational memory so future AI sessions inherit what this audit learned.

The conversation

~3-4 hours · brownfield only

Open your AI assistant — Claude Code, Cursor, VS Code with Copilot Chat, Aider, Windsurf — in the project root. Then walk through these steps. The assistant does the work; you direct.

01
Scope the run. Pick one repo. Ideally not your largest, not your smallest — somewhere in the middle is the most informative. The audit runs on a new branch and never touches main, so risk is zero.
02
Run the audit. Paste this prompt:
Paste this verbatimUse PragmaWorks to audit this project for engineering leadership. Find pragmaworks on npm, install what you need, run the analysis on a new branch (don't touch main), and generate the initial report as a PDF. Score the seven GS properties with evidence, evaluate structural disciplines, assess documentation health, and propose a prioritized remediation plan. Format the output for a manager-readable report.
03
Review the initial report. The PDF tells you where the codebase is today. Score per property, evidence per score, prioritized issue list. This is the document you can forward to peers — your CTO, your CEO, your board — without translation.
04
Run the team-habit analysis. The most under-measured layer in modern engineering organizations. Paste:
Paste this verbatimNow run the team-habit analysis on the last 90 days of commit history. Cover: PR review density, regression test coverage of bugs introduced, AI-introduced bug rate (detect commits with AI-assisted authorship signals and correlate with subsequent bug fixes), commit-size distribution, and collaboration graph across team members. Output as a separate PDF with charts.

If your team has been using AI assistance for the last few months, the AI-bug rate chart is often the most useful single image you can show a leadership audience. It quantifies what you've suspected.

05
Decide whether to remediate now. The initial report includes a remediation plan. You have three options:
  • Apply now — proceed to step 6 in this session.
  • Bring back to your team — share the PDF, discuss in your next planning session, return when ready.
  • Engage PragmaWorks for done-for-you remediation — for larger codebases or compliance-sensitive contexts, our concierge engagement handles the remediation for you.
06
Apply the remediation plan (optional, this session). Paste:
Paste thisApply the top 5 items from the remediation plan on the same branch under GS discipline. For each item, generate the spec change first, then the code change, then the harness verification. Pause before any change that would touch the database schema or the public API — ask me first on those.
07
Get the after-report. Once remediation is done, paste:
Paste thisGenerate the after-report. Same format as the initial one, but with a before/after comparison: coverage delta, structural discipline scores delta, GS rubric delta, regression tests added for past bugs, documentation updates. Include charts.

This is the document you take to your next leadership review. It quantifies what changed, with receipts.
